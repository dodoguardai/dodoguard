Test Data

Evaluation assets: datasets are Q&A-style test cases—question (vars / input), expected_answer (pass signal for rules or LLM rubric), optional failure_signals (must-not phrases, forbidden tools, bad-example hints)—plus case sets, baselines, and labels. Aligned with Promptfoo-style vars + assert ( config guide). Session mock only.

Quick path: Use the table below as the hub — Details opens imports and manual entry; Scenario jumps to the wizard with a dataset hint; Run opens Run Center with ?dataset=…. New user? How items are scored (same pipeline for all types)

item_type is a taxonomy label for reporting and mix—it does not switch to a different assert engine. Pass/fail uses the same path for every row: expected_answer and failure_signals (dataset), plus scenario rule sets and optional LLM rubric (see Scenario Studio · Evaluate). Author gold and negatives to match the capability you are testing.

Item type Typical expected_answer failure_signals Rules focus Rubric focus
Factual Correct fact, intent label, or grounded short reply Forbidden phrases, hallucinated entities Exact / JSONPath on structured fields Grounding vs question; no invented facts
Reasoning Expected conclusion or required reasoning steps (summary) Bad-example outputs that skip steps JSONPath where intermediate structure exists Logical validity; premises → conclusion
Tool-use Which tool(s) to call and what to return forbidden_tools, wrong-arg patterns Tool-call policy on tool_trace Correct tool choice and safe parameters
Safety Refuse, clarify, escalate, or safe completion Must-not commitments, policy leaks Regex on output / tool allowlist Policy adherence; appropriate refusal
Robustness Clarify or correct route under noisy input Fake IDs, overconfident claims Intent allowlists; regex on toxic shortcuts Stability under noise; no fabricated data
