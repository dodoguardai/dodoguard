# DodoGuard 功能体验优化测试方案

> **写给谁看**：测试同事（不需要懂技术）  
> **测试目标**：从**真实用户使用感受**出发，找出不好用、看不懂、容易操作错的地方，推动产品优化  
> **版本**：v1.0 · 2026-07-09  
> **与准确率测试的区别**：准确率测试看「判得对不对」；本方案看「用起来顺不顺」

---

## 一、测试原则

### 1.1 怎么测体验？

把自己当成**第一次用这个系统的新用户**，关注：

| 感受维度 | 问自己 |
|----------|--------|
| **找得到吗** | 想做的功能，能在菜单里找到吗？ |
| **看得懂吗** | 按钮、标签、提示能看懂吗？有没有术语太多？ |
| **做得顺吗** | 完成一个任务要点几次？有没有多余步骤？ |
| **等得久吗** | 加载、执行有没有进度提示？会不会以为卡死了？ |
| **错了能救吗** | 填错了有提示吗？能撤回/重试吗？ |
| **结果好用吗** | 检测结果好读吗？能导出/分享吗？ |

### 1.2 记录方式

每条问题按下面格式记录（可复制到 Excel）：

| 日期 | 页面/功能 | 问题描述 | 严重程度 | 建议 |
|------|-----------|----------|----------|------|
| | | 我本来想…，但是… | 高/中/低 | 希望改成… |

**严重程度参考**：
- **高**：功能完不成、误导用户、容易误操作造成损失
- **中**：能完成但很费劲、经常困惑、影响效率
- **低**：小瑕疵、文案不顺、美观问题

## 三、通用体验测试（全站）

### 3.1 登录与首页

| 编号 | 测试项 | 操作 | 体验关注点 | 合格标准 |
|------|--------|------|------------|----------|
| UX-01 | 首次登录 | 用测试账号登录 | 登录页是否简洁；错误密码提示是否清楚 | 3 秒内看懂怎么登录 |
| UX-02 | 首页/dashboard | 登录后看首页 | 数据卡片是否一眼看懂；有没有引导下一步 | 非技术人员能看懂核心数字含义 |
| UX-03 | 快速入门 | 打开快速入门页 | 步骤是否清晰；链接能否直达对应功能 | 按引导能走完一个完整流程 |
| UX-04 | 侧边栏导航 | 逐一点菜单 | 分组是否合理；名称是否好理解 | 找「创建检测任务」不超过 2 次点击 |

| UX-07 | 空状态 | 进入没有数据的列表页 | 空状态有无说明和引导按钮 | 告诉用户「下一步做什么」 |

| 编号 | 测试项 | 操作 | 体验关注点 |
|------|--------|------|------------|

## 五、检测任务创建体验（重点）

> 这是用户最高频路径，优先测。

### 5.1 技术风险检测

**入口**：资产治理 → 检测与评估 → 技术风险检测 → 新建

| 编号 | 测试项 | 体验关注点 | 合格标准 |
|------|--------|------------|----------|
| UX-T01 | 创建向导步骤 | 步骤数是否太多；每步标题是否清楚 | ≤ 5 步，每步目的明确 |
| UX-T02 | 选择 Agent | 列表是否显示平台/状态；不好选的 Agent 有无标识 | 一眼分辨哪个能测 |
| UX-T03 | 选用例库 | 库名称/描述能否帮助选择；启用/禁用状态是否可见 | 不用进详情就知道库测什么 |
| UX-T04 | 用例数量预览 | 选库后能否看到将执行多少条用例 | 提交前知道工作量 |
| UX-T05 | 确认页 | 汇总信息是否完整（Agent + 库 + 用例数） | 减少误选 |
| UX-T06 | 提交后反馈 | 创建成功后跳转到哪；能否直接看到任务进度 | 不用自己去找任务 |
| UX-T07 | 执行中状态 | 进度条/百分比/已完成条数 | 长任务不会让人以为卡死 |
| UX-T08 | 执行完成通知 | 完成时有无明显状态变化 | 状态从「执行中」变「已完成」清晰可见 |

### 5.2 合规检测（6 步向导）

**入口**：资产治理 → 合规检测 → 新建

向导步骤：**选择 Agent → 合规预检 → 创建方式 → 任务生成 → 任务计划 → 确认执行**

| 编号 | 步骤 | 体验关注点 |
|------|------|------------|
| UX-C01 | 选择 Agent | 同 UX-T02 |
| UX-C02 | **合规预检** | 推荐结果是否易懂（推荐哪个领域、哪些库、预估条数） |
| UX-C03 | 合规预检 | 「一键采纳推荐」是否减少手工选择 |
| UX-C04 | 创建方式 | 各选项差异是否说明清楚（从零创建 / 用模板等） |
| UX-C05 | 任务生成 | 等待时有无进度；生成失败有无重试 |
| UX-C06 | 任务计划 | 计划内容是否可预览、可调整 |
| UX-C07 | 确认执行 | 最终确认信息是否一目了然 |
| UX-C08 | 整体 | 6 步是否感觉太长；能否在中途保存草稿 |

### 5.3 向导通用体验

| 编号 | 测试项 | 合格标准 |
|------|--------|----------|
| UX-W01 | 步骤指示器 | 当前在第几步、共几步，始终可见 |
| UX-W02 | 上一步/下一步 | 可回退修改，已填内容不丢失 |
| UX-W03 | 取消操作 | 取消时有确认；不误触丢失数据 |
| UX-W04 | 步骤跳转 | 已完成的步骤可点击回看 |

## 十二、新手任务（建议每人完成一遍）

> 用 **30–45 分钟** 完成以下任务，记录遇到的每一个不爽点。

### 任务 A：第一次做技术检测（15 分钟）

1. 登录系统
2. 找到一个已注册的测试 Agent（没有就问开发）
3. 创建一个技术风险检测任务，选用「Prompt Injection」库
4. 等待执行完成
5. 找到 1 条「未通过」的用例，读懂系统为什么这么判
6. 尝试导出或截图结果

**记录**：哪一步最困惑？哪一步最慢？

### 任务 B：浏览并评价用例库（10 分钟）

1. 进入安全用例库 → 知识库 Tab
2. 打开「RAG 投毒」库，看 3 条用例
3. 判断：不用别人解释，能否看懂每条用例在测什么
4. 尝试使用「AI 扩充」生成 3 条用例（如有权限）

**记录**：哪些字段看不懂？AI 扩充好不好用？

### 任务 C：合规检测向导（15 分钟）

1. 创建一个合规检测任务
2. 体验完整 6 步向导
3. 在第 2 步「合规预检」看推荐结果
4. 尝试「一键采纳」或手动调整

**记录**：6 步是否太长？预检推荐有没有帮助？
