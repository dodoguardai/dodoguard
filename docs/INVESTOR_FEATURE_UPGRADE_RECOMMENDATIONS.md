# DodoGuard 面向投资人的功能升级与战略建议

**文档用途**：融资材料中的「产品护城河 + 18～36 个月能力规划」附件；与 [Promptfoo](https://www.promptfoo.dev/) 等国际头部产品对标时，突出 **差异化赛道与商业化闭环**。  
**前提**：当前仓库已具备 **评测/红队引擎（上游能力）**、**企业多租户 API**、**漏洞与攻击任务**、**多平台配置审计**、**Dify 专项渗透** 等基础（详见 [DODOGUARD_CURRENT_SYSTEM.md](./DODOGUARD_CURRENT_SYSTEM.md)）。

---

## 1. 市场叙事：为什么现在值得投

全球企业正在从「试用 ChatGPT」转向 **生产级 Agent + 工作流 + MCP 工具链**。安全痛点从单一「模型越狱」扩展为：

- **应用层**：提示注入、工具滥用、会话劫持、越权与业务规则绕过  
- **数据层**：RAG 泄露、PII 外泄、跨租户混淆  
- **工程层**：低代码/Agent 平台（如 Dify 生态）配置错误、密钥暴露、不可审计的自动化  

国际头部产品（如 Promptfoo 所代表的品类）已在 **红队自动化、评测、开发工作流嵌入** 上教育了市场。DodoGuard 若要成为「全世界最牛逼」梯队，需要在三件事上 **超越单点工具**：

1. **系统级风险记录**（可审计、可对比、可进合规包）  
2. **深度平台绑定 + 开放生态**（API、CI、ITSM、MCP 一体）  
3. **持续保障**（漂移检测、订阅化运营、渠道/MSSP）

以下功能升级按 **投资人最关心的壁垒与收入** 排序。

## 2. 旗舰能力矩阵（建议对外展示的「世界级」蓝图）

### 2.1 Agent 安全态势与证据链（Trust + Compliance）

| 能力 | 投资人价值 | 说明 |
|------|------------|------|
| **统一风险视图** | 大单必备 | 组织 × 目标 Agent：动态测试结果 + 静态配置审计 + 开放漏洞 + 报告，一屏聚合 |
| **不可变风险快照** | 审计可信度 | 每次任务/审计生成带哈希的快照；支持版本线对比（风险是否回退） |
| **Compliance Bundle** | 缩短采购周期 | 一键导出 ZIP：报告、CSV、脱敏审计记录、方法论说明，贴合 SOC2 / 内审 |
| **证据链元数据** | 抗质疑 | 操作者、输入/配置哈希、模型提供方、时间戳、环境标签（prod/staging） |

### 2.2 Policy-as-Code 与 CI 门禁（工程化护城河）

| 能力 | 投资人价值 | 说明 |
|------|------------|------|
| **组织级策略包** | 与「仅跑一次渗透」差异化 | 密钥、RAG、工具白名单、严重级别阈值等规则即代码 |
| **GitHub / GitLab 官方模板** | 开发者扩散 | PR 上跑配置审计；超阈 block merge；评论里带修复链接 |
| **稳定公共 API + Webhook** | 平台化收入基础 | Scoped Token、幂等、任务/报告/审计资源模型；完成或超阈通知 |

### 2.3 威胁情报与方法论资产（品牌与复购）

| 能力 | 投资人价值 | 说明 |
|------|------------|------|
| **双标签分类法** | 学术与采购双语 | 内部分类 + 映射 **MITRE ATLAS**、**OWASP LLM Top 10** 等 |
| **行业报告模板** | 垂直行业扩展 | 金融、医疗、政务等措辞与免责模板内置 |
| **可复现基准包** | 技术领导力 | 匿名化、版本化的公开场景包 + 「我们如何测」白皮书 |

### 2.4 企业采购与规模化（NDR 类指标）

| 能力 | 投资人价值 | 说明 |
|------|------------|------|
| **SSO（SAML/OIDC）+ 可选 SCIM** | 企业准入门槛 | 与 RBAC 已有基础衔接 |
| **区域与租户隔离叙事** | 出海与政务 | Region 绑定、数据流说明、部署拓扑文档化 |
| **Trust Center** | 缩短安全问卷 | 子处理器、加密、留存、事件响应一页汇总 |
| **配额、席位、用量计量** | 可预测的 ARR | 组织级仪表盘 + 套餐边界清晰 |
| **MSSP / 渠道模式** | 放大分销 | 多客户只读视图、委托运行、伙伴级审计 |

### 2.5 差异化：「平台原生 + 动态攻击」双轮驱动

在 Promptfoo 强调的 **红队、评测、CI、社区威胁情报**（见 [官网产品叙事](https://www.promptfoo.dev/)）之外，DodoGuard 已具备 **Dify 渗透与多平台配置审计** 雏形。建议升级为明确口号：

- **「低代码 / Agent 平台原生安全」**：Dify / 同类工作流的一键深度测试 + 配置漂移监控。  
- **「静态 + 动态」闭环**：同一漏洞 ID 在配置层与运行时层同时验证，减少误报与漏报。

## 3. 分阶段路线图（建议写进 BP 的里程碑）

### Phase 0～6 个月（验证收入与复购）

- 统一风险视图（MVP）+ Compliance Bundle（最小可用）  
- 公共 API v1 稳定化 + Scoped Token + 基础 Webhook  
- 发现项双标签（内部 + OWASP LLM 映射）  
- Trust Center 骨架与安全文档对齐产品实际行为  

### Phase 6～12 个月（企业扩张）

- 风险快照与版本对比；定时/事件触发再审计与告警  
- CI 门禁模板（GitHub/GitLab）与 Policy-as-Code 初版  
- SSO；行业报告模板 packs  

### Phase 12～24 个月（品类定义者）

- 区域/部署隔离与大型企业架构故事  
- ITSM（Jira/ServiceNow）一键建单与字段映射  
- MSSP/渠道工作台；多模型评审（高敏场景共识）  
- 可复现公开基准与年度安全报告品牌活动

## 4. 刻意不做或后置（避免与巨头正面消耗）

- **通用推理侧 Guardrails 网关**：与云厂商/模型厂产品线重叠度高，除非有明确客户与协议层差异化，否则不作为主叙事。  
- **无客户验证的泛化「超大模型」能力**：与买方自研战略重复，性价比低。  

资源应集中在 **审计证据、工作流嵌入、平台绑定、合规出口**。

---

## 5. 投资人 DD 时建议准备的「对标回答」

1. **与 Promptfoo / 国际开源的关系**：引擎与社区红利来自成熟评测/红队基座；商业化与护城河在 **多租户、审计、垂直平台（Dify 等）、合规交付**。  
2. **技术壁垒**：漏洞库 + 场景插件 + 配置解析深度 + 证据链产品化，而非单次 pentest 服务。  
3. **壁垒是否可防御**：Policy-as-Code、CI 嵌入、快照与合规包提高 **切换成本**；渠道与 MSSP 提高 **分发壁垒**。
