# AI 安全平台 V1-V5 开发功能清单（结合当前系统）

> 目标：基于当前 DodoGuard/Promptfoo 代码现状，给出按阶段可落地的开发清单。  
> 参考现状文档：`docs/DODOGUARD_CURRENT_SYSTEM.md`、`docs/PRODUCT_STAGED_ROADMAP.md`。

---

## 当前系统能力基线（已具备）

- 扫描与评测引擎：Eval、Red Team、Dify/FastGPT/n8n/Coze 专项扫描脚本
- 企业 API 主体：auth、users、organizations、attack-tasks、findings、reports、dashboard 等
- 基础业务对象：漏洞库、攻击任务、目标 Agent、报表、队列
- 静态配置审计：Dify/Coze/FastGPT/n8n 配置审计路由
- 前端控制台基础模块：任务、漏洞、报表、仪表盘（已在 `frontend/`）
- 数据层基础：组织、用户、团队、漏洞、任务、结果、审计日志等表结构

---

## V1 扫描器（AI Security Scanner）

**阶段目标**：快速发现问题并产出首份风险报告。  
**商业目标**：最低采购门槛、最快 PoC 落地。

### 已有能力（可复用）
- 动态攻击扫描（red team + 专项渗透）
- 静态配置审计（多平台）
- 基础报告输出链路

### 需开发/补齐
- 统一风险评分模型（严重度、置信度、可利用性、影响面）
- 发现项标准化数据契约（证据、复现步骤、修复建议字段统一）
- 扫描模板库（按业务场景一键扫描）
- 报告模板分层（技术版/管理版）
- 扫描资产画像（目标类型、环境、数据敏感级别）

### 交付物
- V1 风险报告（PDF/HTML）
- 统一风险分级规则 v1
- 标准扫描模板集（基础、RAG、Agent、API）

---

## V2 验证平台（AI Security Validation）

**阶段目标**：从“发现问题”升级为“是否可上线”的决策能力。

### 已有能力（可复用）
- 扫描结果、漏洞对象、任务对象
- 报表与任务执行基础能力

### 需开发/补齐
- 安全基线模板中心（行业/业务线/环境）
- Pass/Fail 判定引擎（必须项、阻断项、加权项）
- 回归验证机制（修复后复测、对比前后结果）
- 环境对比（Dev/UAT/Prod）
- 验证结论对象（上线建议、阻断原因、责任建议）

### 交付物
- 验证结论页（可上线/不可上线）
- 基线模板管理页
- 回归验证流水（版本化）

---

## V3 发布门禁（AI Release Gate）

**阶段目标**：将高风险应用阻断在发布之前。  
**商业目标**：形成持续订阅与流程嵌入。

### 已有能力（可复用）
- 后端 API 与任务执行能力
- CLI 体系（可作为 CI 接入基础）

### 需开发/补齐
- 阈值策略中心（项目/环境维度）
- CI/CD 集成接口（GitHub/GitLab/Jenkins）
- 门禁状态 API（通过/失败/阻断）
- 审批与例外机制（时效、审批记录、到期回收）
- 自动阻断与回写（PR 状态、流水线结果）

### 交付物
- 发布门禁策略配置
- CI 接入文档与示例模板
- 例外审批工作流 v1

---

## V4 持续治理（AI Security Governance）

**阶段目标**：持续跟踪修复、漂移与复发。  
**商业目标**：提高续费率与组织级渗透。

### 已有能力（可复用）
- 审计日志基础表
- 任务、发现、报表对象

### 需开发/补齐
- 定时复测调度器（周期任务、失败重试）
- 风险趋势看板（时间维度、资产维度、团队维度）
- 漏洞生命周期与责任归属（指派、状态流转）
- SLA 管理（时限、超时、升级）
- 工单系统集成（Jira/飞书/企业微信等）

### 交付物
- 治理驾驶舱（趋势 + SLA + 责任）
- 复测计划管理
- 工单联动能力

## V5 控制平面（AI Security Control Plane）

**阶段目标**：统一管理企业 AI 资产、策略与合规映射。  
**商业目标**：平台化能力与估值提升。

### 已有能力（可复用）
- 多租户与 RBAC 基础对象
- 漏洞标准字段（CWE/MITRE/OWASP 映射基础）

### 需开发/补齐
- 资产关系图谱（应用-模型-数据-工具调用关系）
- 全局策略引擎（组织级策略、继承与覆盖）
- 合规映射中心（标准框架到控制项映射）
- 管理层报表（组织级风险 KPI）
- 控制平面 API（统一编排、跨系统接入）

### 交付物
- 控制平面总览页
- 资产关系图与策略图谱
- 合规映射与管理层报告模板

## 升级后使用者导航说明（侧栏与页面跳转）

> 说明：控制台主导航为**左侧功能菜单**（`frontend` 中 `AppSidebar` / `sidebar-data`）。以下按 **V1–V5 升级后的信息架构**描述「使用者点哪里、接着跳哪里」；具体路由以实现为准。

### 侧栏分组的心智模型（推荐）

把侧栏理解为一条产品线：

**扫描发现问题 → 发现/报告看清楚 → 验证（敢不敢上线）→ 门禁（能不能发布）→ 治理（长期谁修、复发与 SLA）→ 控制面（全公司资产与策略）**

日常 **约 80% 时间**停留在前两段（扫描 + 结果）；后面几段在「上线决策、流程嵌入、组织治理、高管/尽调视图」时再进入。

### 四类典型使用者路径

#### 1）一线安全 / 渗透（最常用）

**目的：扫一把、看清风险、交出材料**

1. **扫描与发现** → **安全测试** → 「全部任务」或按平台（Dify / Coze / FastGPT / n8n 等）
2. 打开 **任务详情** → 进入某次 **运行**
3. **风险与报告** → **发现** → **发现详情**（证据、建议）
4. **报告** → 导出或分享给业务/管理岗

**页面内跳转（建议产品上必做）**：发现详情 → 「回溯本次运行」「回溯所属任务」，避免用户在菜单里来回找。

#### 2）要做上线决策的角色（V2 验证）

**目的：不只是漏洞清单，而是 Pass/Fail**

1. 从 **任务/运行结果页** 进入「上线验证 / 基线检查」（减少多点一层菜单）
2. 或从侧栏 **验证与基线** → **验证运行列表**（复盘、审计时）
3. 验证页展示：**通过/未通过**、未过项、与基线差异  
4. 未通过时：一键跳到 **发现**（Evidence），或跳到 **报告**（验证结论版式）

#### 3）研发 / DevOps（V3 发布门禁）

**目的：流水线失败能快速归因**

1. CI / IM 通知中的链接 → **发布门禁** → **某次门禁运行**
2. 门禁页展示：关联仓库/分支/构建号、阈值、失败原因
3. 从门禁记录跳到 **验证** 或 **任务/运行**（原始证据链）
4. 例外流程：**申请 / 查看例外** → 仍可从同一门禁记录进入追溯

**习惯**：一线研发多起始于 **deep link**，侧栏「发布门禁」更多是安全负责人看汇总列表。

#### 4）管理与资产视角（V4 治理 + V5 控制面）

**治理（V4）**

1. **持续治理** → **复测计划** / **待办与 SLA 看板**
2. 点击逾期或复发项 → **发现详情**（责任人、截止日）
3. 从发现 **打开关联任务/运行** 做复测  
4. **仪表盘** 升级为带「趋势、通过率、SLA」的摘要，再下钻到治理或发现

**控制面（V5）**

1. **控制平面** → **资产图谱** → 点选 **应用 / Agent / 模型** 等节点
2. 节点面板：**发起扫描**、**查看策略命中**、**关联门禁/验证历史**
3. **全局策略** / **合规映射**：从侧栏进入做「规则与标准」查询；从策略反查资产后再跳回图谱

### 产品规则（避免升级后菜单「变多就迷路」）

| 层级 | 职责 |
|------|------|
| **侧栏** | 用户「我要进哪一大块」（扫描、结果、验证、门禁、治理、控制面、组织、系统） |
| **页面内关联链接 / 按钮** | 沿同一条 **证据链** 下钻：任务 ↔ 运行 ↔ 发现 ↔ 报告 ↔ 验证 ↔ 门禁 ↔ 资产节点 |

统一锚点实体建议固定为四类，便于全版本跳转一致：**目标资产**、**扫描/验证/门禁运行**、**发现（Finding）**、**报告（Report）**。
