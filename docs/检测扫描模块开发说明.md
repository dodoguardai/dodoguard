# 检测扫描模块开发说明

## 1. 本次开发范围

本次按照原型中“检测扫描”和“安全配置”的顺序，新增四部分功能：

1. 技术风险检测
2. 风险整改中心
3. 技术安全检查用例库
4. 能力组件风险库

这三部分承接新版治理流程：

`资产入库 -> 组件识别 -> 组件级检测 -> 智能体整体检测 -> 综合风险评估 -> 风险整改 -> 复测验证 -> 报告审计 -> 上线观测`

## 2. 页面与路由

| 功能 | 路由 | 说明 |
| --- | --- | --- |
| 技术风险检测 | `/scan/technical-risks` | 展示技术检测任务台账、检测来源、检测对象、进度和风险统计 |
| 风险整改中心 | `/scan/remediation` | 承接检测发现项，完成整改证据、复测、关闭、重新整改和风险接受 |
| 技术安全检查用例库 | `/scan/security-cases` | 管理检测场景库、用例数量、检测方式、启用状态和标准依据 |
| 能力组件风险库 | `/scan/capability-risks` | 管理 Skill、MCP、工具/API、大模型、知识库等组件级风险 |

入口已加入侧边栏“检测扫描”菜单组。

## 4. 当前实现状态

### 4.1 技术风险检测

当前页面提供：

- 检测任务指标卡
- 治理流程位置条
- 任务状态筛选
- 关键词搜索
- 检测任务表格
- 检测进度展示
- 高 / 中 / 低风险数量展示
- 从资产台账发起检测的跳转入口
- 执行检测并生成风险发现项
- 按规则自动转为整改任务并推送到风险整改中心

当前数据已接入服务端接口 `/api/v1/scan/tasks` 与 `/api/v1/scan/tasks/:id/execute`，新组织首次访问会初始化一组组织级样例任务。

### 4.2 风险整改中心

当前页面提供：

- 风险发现项与整改任务指标
- 按责任人、风险等级、整改状态筛选
- 整改任务列表
- 责任人处理
- 提交整改证据
- 复测通过后关闭
- 复测失败后重新整改
- 风险接受并关闭发现项

该页面承接完整测试流程：

`新建评估任务 -> 选择检测对象 -> 执行检测 -> 生成风险发现项 -> 转成整改任务 -> 推送整改中心 -> 责任人处理 -> 提交整改证据 -> 复测验证 -> 关闭 / 重新整改 / 风险接受`

版本追溯已接入闭环：

- 检测任务记录 `asset_version`、`asset_snapshot_id` 和 `component_versions`
- 风险发现项继承检测时的 Agent 版本、快照和组件版本
- 整改任务记录 `source_asset_version` / `source_snapshot_id`，并可记录整改后的 `target_asset_version` / `target_snapshot_id`
- 复测记录记录 `retest_asset_version` / `retest_snapshot_id`
- 风险关闭或风险接受的结论绑定到具体版本，不默认扩散到后续版本

### 4.3 技术安全检查用例库

当前页面提供：

- 场景库总览指标
- 按场景域筛选
- 场景库卡片
- 用例数量、检测方式、发布状态、启用状态展示
- 标准依据展示
- 新建场景库、启用、维护样本的交互占位

当前数据已接入服务端接口 `/api/v1/scan/case-libraries`，支持创建场景库、启用/关闭场景库，以及维护场景库下的检测用例。

### 4.4 能力组件风险库

当前页面提供：

- 组件风险总览指标
- 按组件类型筛选
- Skill / MCP / 工具 / 大模型 / 知识库风险卡片
- 风险等级、影响资产、检测规则、检查项展示
- 同步风险、加入检测、详情交互占位

当前数据已接入服务端接口 `/api/v1/scan/capability-risks`，支持同步/新增组件风险、更新风险影响范围，以及维护风险规则。

## 8. 与资产入库的关系

资产入库负责生成可治理对象和能力组件清单：

- Agent 主资产来自 `agent_assets`
- 组件清单来自 `agent_asset_components`
- 治理阶段记录在资产 `metadata.governanceWorkflow`

检测扫描模块应基于 `asset_id` 和组件清单生成检测任务：

1. 资产台账选择 Agent
2. 根据组件类型推荐检测计划
3. 从技术安全检查用例库选择用例
4. 从能力组件风险库匹配组件级规则
5. 执行检测后生成 Findings
6. 更新资产治理阶段和风险等级
