本原型对应的「改造要点」
  • 统一模型：列表行区分 runtime / config_audit，与现有 attack_results + 配置审计 findings 对齐。
  • 筛选落地：与后端约定 search、status、riskLevel、findingType、hasTicket、agentId、taskId 等 query，修正分页 total。
  • 内置工单网关（参考 OpenClaw）：Finding 仅调用 POST /ticket-gateway/issues（示意）；网关按组织配置路由到 adapterId（jira、snow、feishu…）。新增平台 = 新适配器 + 注册表项；可选 YAML Skills 做标题/优先级/项目路由（类 OpenClaw Skills 编排）。
  • ITSM 存储：Finding 与外部单多对多；存 externalKey、adapterId、url、state、lastSyncedAt；Inbound Webhook 回写状态。
  • 详情证据链：多轮对话、ruleHits、关联审计 Run / 任务 ID，支撑 Compliance Bundle 导出。

内置工单网关 · Ticket Gateway

UI 与 Finding 服务不直连各厂商 API，只对接 DodoGuard 网关；由网关加载已启用适配器并完成鉴权、重试与审计日志。模式对齐 OpenClaw 等方案的「连接器 + 可编排 Skills」：用声明式规则把 Finding 字段映射到 Jira fields / SN payload / 飞书卡片等。
